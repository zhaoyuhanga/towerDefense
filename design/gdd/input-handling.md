# 输入处理系统 (Input Handling System)

> **Status**: In Design
> **Author**: user + game-designer
> **Last Updated**: 2026-06-01
> **Implements Pillar**: Pillar 4 — 你造你观你调（输入是"造"和"调"的物理通道）

## Overview

输入处理系统是玩家所有物理操作到游戏逻辑的翻译层。它接收 Godot 的原始 `InputEvent`（鼠标点击、移动、拖拽），将其转化为语义明确的游戏动作（放置方块、选择塔、拖拽合星、使用技能），并根据当前游戏阶段（建造/战斗）路由到对应的游戏系统。

玩家不与此系统交互——他们通过鼠标与游戏世界交互。但输入处理系统定义了什么时候能做什么：建造阶段才能放方块、战斗阶段只能用应急技能、拖拽合星需要两个同星塔。没有输入处理，鼠标点击只是一堆坐标——有了它，点击才变成"在这里放一座塔"。

## Player Fantasy

玩家不感受输入处理本身。他们感受的是操作的即时性和确定性——拖拽合星时塔跟着鼠标走、点击放塔时预览方块贴合格线、右键移除方块时瞬间消失。输入处理是实现"即点即得"手感的沉默保障。

- **服务于 Pillar 4（你造你观你调）**：建造阶段的操作流畅度直接影响"筑城"体验
- **参考体验**：Bloons TD 6 的塔放置手感、2048 的拖拽合成手感

## Detailed Design

### Core Rules

1. **阶段门控**：建造阶段和战斗阶段有不同的输入许可集。
2. **鼠标独占**：所有输入来自鼠标。MVP 无键盘快捷键。
3. **单路由**：每个原始事件只产生一个游戏动作。
4. **拖拽检测**：鼠标按下后移动超过 3px 才算拖拽，否则算点击。

### 输入动作映射

#### 建造阶段

| 原始输入 | 目标 | 游戏动作 | 路由到 |
|----------|------|---------|--------|
| 左键点击 | EMPTY 格 | 放置当前选中物 | 防御塔 / 障碍方块 |
| 左键点击 | TOWER 格 | 选择该塔 | 防御塔 |
| 左键点击 | BLOCK 格 | 选择该方块 | 障碍方块 |
| 左键拖拽 | TOWER→同类型同星 | 合星 | 合星升级 |
| 左键拖拽 | TOWER→非同类型/星 | 弹回原位 | 合星升级 |
| 左键释放 | EMPTY 格（拖拽中） | 取消拖拽 | — |
| 右键点击 | BLOCK | 移除方块 | 障碍方块 + 经济 |
| 右键点击 | TOWER | 出售塔 | 防御塔 + 经济 |
| 右键点击 | 任意（有选择时） | 取消选择 | — |
| 鼠标移动 | 任意 | 更新光标+预览 | 棋盘网格 |

#### 战斗阶段

| 原始输入 | 目标 | 游戏动作 | 路由到 |
|----------|------|---------|--------|
| 左键点击 | 应急技能按钮 | 激活技能 | 应急技能 |
| 左键点击 | 棋盘内 | **无响应** | — |
| 右键点击 | 棋盘内 | 取消选择 | — |
| 鼠标移动 | 棋盘内 | 更新光标 | 棋盘网格 |

### 不允许的操作

- 战斗阶段棋盘上不响应左键/右键
- 不能拖拽怪物
- 不能拖拽方块
- ENTRANCE/EXIT 格不可修改

### 冲突优先级

UI 按钮 > 棋盘格（塔 > 方块 > 空格）> 虚空

## Formulas

输入处理系统没有数学公式。唯一的判断逻辑：

**拖拽检测**：`is_drag = (mouse_pos - drag_start_pos).length() > DRAG_THRESHOLD`

| 变量 | 类型 | 值 | 说明 |
|------|------|-----|------|
| `DRAG_THRESHOLD` | float | 3.0 | 像素阈值。小于=点击，大于=拖拽 |

## Edge Cases

- **双击**：第一次点击选中塔，第二次点击在同一塔上 → 无额外效果（不触发"合星自己"）
- **拖拽中途右键**：拖拽中按下右键 → 取消拖拽，塔弹回原位
- **拖拽到棋盘外**：释放时坐标越界 → 取消拖拽，塔弹回原位
- **阶段切换时正在拖拽**：建造→战斗转换时强制取消进行中的拖拽，塔弹回原位
- **快速连续点击不同塔**：每次点击独立处理——选中新塔，取消旧选择
- **点击 UI 穿透到棋盘**：UI 层优先拦截——落在按钮区域内的点击不传递给棋盘

## Dependencies

零上游依赖。棋盘网格的 `world_to_grid()` 是 Soft 依赖（棋盘未初始化时输入处理仍可运行，只是没有有效坐标）。

| 下游系统 | 关系 | 路由的动作 |
|----------|------|----------|
| 准备阶段 | Hard | 准备/开始按钮点击 |
| 障碍方块 | Hard | 放置方块、移除方块 |
| 防御塔 | Hard | 放置塔、选择塔、出售塔 |
| 合星升级 | Hard | 拖拽合星 |
| 应急技能 | Hard | 技能按钮点击 |
| HUD/UI | Hard | 所有 UI 按钮路由 |
| 棋盘网格 | Soft | `world_to_grid()` 坐标转换 |

## Tuning Knobs

| Knob | 默认值 | 安全范围 | 说明 |
|------|--------|----------|------|
| `DRAG_THRESHOLD` | 3 | 2–5 px | 太小=手抖变拖拽；太大=拖拽需要"使劲拉"才触发 |

## Visual/Audio Requirements

不适用。输入处理是纯逻辑层——无视觉表现。以下音频反馈由对应系统触发（输入处理本身不发声）：

| 输入事件 | 音效 | 触发系统 |
|---------|------|---------|
| 放置塔/方块确认 | 点击音效 | 防御塔/障碍方块 |
| 合星成功 | 合成音效 | 合星升级 |
| 合星失败 | 拒绝音效 | 合星升级 |
| 技能激活 | 技能音效 | 应急技能 |

## UI Requirements

不适用——输入处理没有独立的 UI 界面。它处理 UI 按钮的点击事件，但 UI 本身由 HUD/UI 系统渲染。

> 输入处理的唯一"UI"是光标——但光标样式切换建议由各自系统直接管理（放置预览跟随 = 障碍方块/防御塔系统；拖拽中 = 合星升级系统）

## Acceptance Criteria

- **GIVEN** 建造阶段，**WHEN** 左键点击 EMPTY 格，**THEN** 当前选中的塔/方块被放置在该格
- **GIVEN** 建造阶段，**WHEN** 左键拖拽 1 星炮塔到另一座 1 星炮塔上，**THEN** 触发合星
- **GIVEN** 建造阶段，**WHEN** 左键拖拽炮塔到冰塔上，**THEN** 两塔弹回原位（合星失败）
- **GIVEN** 战斗阶段，**WHEN** 左键点击棋盘格，**THEN** 无游戏动作发生
- **GIVEN** 战斗阶段，**WHEN** 左键点击可用应急技能按钮，**THEN** 技能被激活
- **GIVEN** 建造阶段，**WHEN** 右键点击 BLOCK 格，**THEN** 方块被移除，金币返还
- **GIVEN** 鼠标按下后移动 2px 释放（<3px 阈值），**WHEN** 移动结束，**THEN** 识别为点击而非拖拽

## Open Questions

1. **光标样式管理**：放置预览方块（半透明跟随光标）由输入系统渲染还是由方块/塔系统各自渲染？→ 实现阶段建 ADR
2. **快捷键预留**：V1.0 是否需要键盘快捷键（如数字键 1/2/3 切换塔类型、空格键开始波次）？当前 MVP 不需要，但代码结构应为扩展留出空间
3. **输入缓冲**：如果玩家在阶段切换动画期间（0.5-0.8s）点击了棋盘，输入应该排队等待切换完成还是丢弃？→ 建议丢弃（避免误操作），但需确认
