# Accessibility Requirements

> **Status**: Draft
> **Created**: 2026-06-01
> **Target Tier**: Basic (MVP) — 桌面端单机游戏的最低无障碍标准
> **Platform**: Windows / macOS Desktop
> **Input**: Keyboard/Mouse only (no gamepad, no touch)

## 1. Scope & Commitment

本游戏是一款桌面端单机塔防游戏。MVP 阶段承诺满足**基础无障碍层**——不追求 WCAG 完整合规，但确保以下玩家群体不会被排除：

- 色觉障碍玩家（约 8% 男性、0.5% 女性）
- 无声环境玩家（办公室、公共场所）
- 精细运动障碍玩家（右键菜单作为拖拽替代方案）
- 低视力玩家（可读字号、高对比度）

V1.0 阶段评估是否需要屏幕阅读器支持（Godot 4.5+ AccessKit）。

## 2. Visual Accessibility

### 2.1 Color Independence

> **规则**: 没有任何关键游戏信息仅通过颜色传达。

| 场景 | 颜色传达的信息 | 形状/图标补充 |
|------|--------------|-------------|
| 放置预览 (合法/非法) | 绿色 = 可放，红色 = 不可放 | ✓/✗ 图标叠加 |
| 塔类型区分 | 炮塔红、冰塔蓝、箭塔绿 | 独特的塔形状/轮廓 |
| 怪物词缀 | 不同颜色的边框/光环 | 词缀图标 (💀🔥❄) |
| 阶段切换 | UI 按钮显隐 | 阶段标签文字 (PREP/BATTLE) |
| HP 危机状态 | 红色闪烁边框 | HP 数字 + 条形图 |

### 2.2 Contrast

- 所有 UI 文字与背景对比度 ≥ 4.5:1（WCAG AA 标准）
- 关键 HUD 元素（波数、金币、HP）对比度 ≥ 7:1
- 网格线 (`#4A6078`) 与棋盘底色 (`#263040`) 对比度 ≈ 3:1——符合"背景元素可略低"的例外

### 2.3 Text Size

- HUD 核心信息（波数、金币）: ≥ 16px
- UI 按钮标签: ≥ 14px
- Tooltip 浮层文字: ≥ 12px
- 伤害数字弹出: ≥ 14px（短暂显示，可略小于常驻文字）

### 2.4 Flashing & Motion

- 无闪烁频率 > 3 次/秒的内容（避免光敏性癫痫触发）
- 合星动画 0.6-0.8s——属于"过渡动画"，非闪烁
- 危机红闪：脉冲频率 1-2 次/秒——安全范围内
- V1.0 评估是否需要"减少动态效果"选项

## 3. Auditory Accessibility

### 3.1 Silent Mode Compatibility

> **规则**: 游戏在完全静音下必须可玩。所有关键信息通过视觉传达。

| 通常依赖声音的信息 | 视觉替代方案 |
|-------------------|-------------|
| 塔攻击命中 | 伤害数字弹出 + 怪物受击闪烁 |
| 合星成功/失败 | 5 阶段视觉动画 / 弹回动画 |
| 怪物死亡 | 死亡粒子效果 + 金币飘出 |
| 波次开始 | UI 波数跳动动画 |
| 怪物突破防线 | HP 条减少 + 红色闪烁 + 路径伤痕 |
| UI 按钮反馈 | 按钮按下缩放动画 |

### 3.2 Audio Levels

- 音量控制: 主音量 / 音效 / 音乐 三个独立滑块
- 默认音量: 主 100% / 音效 100% / 音乐 80%
- 静音: 所有滑块可拖到 0

## 4. Motor Accessibility

### 4.1 Click Precision

- 棋盘格尺寸 56×56px——远大于标准按钮最小可点击区域 (44×44px)
- UI 按钮最小尺寸 44×44px（含 padding）
- **拖拽替代方案**: 右键菜单合星——不依赖精确拖拽操作即可完成合星
- 拖拽阈值 3px——避免手抖被误判为拖拽

### 4.2 Timing Tolerance

- 所有操作无时间限制——PREP 阶段无计时器
- 合星动画播放期间不阻塞其他操作（塔攻击独立运行）
- 阶段切换动画 0.5-0.8s 期间的输入被丢弃——对玩家不可见

### 4.3 No Rapid-Tap Requirements

- 无需要快速连续点击的机制
- 无需要精确 timing 的操作（如 QTE）
- 唯一需要时序的操作——拖拽合星——右键菜单提供了纯点击替代方案

## 5. Cognitive Accessibility

### 5.1 Information Architecture

- 核心游戏状态（波数、金币、HP）始终可见——玩家不需要记忆
- 下一波预览在 PREP 阶段显示——决策前有完整信息
- 塔属性 tooltip 按需显示——不占用常驻屏幕空间
- 阶段切换明确：UI 布局变化传达了"现在能做什么"

### 5.2 Tutorial & Onboarding

MVP 方案（3 波渐进教程）:
- 第 1 波: 只有一种塔——教方块放置
- 第 2 波: 引入合星——教拖拽 + 右键菜单合星
- 第 3 波: 引入应急技能——教战斗阶段操作

### 5.3 Error Prevention

- 放置预览（Pattern 4）在放置前确认位置合法性
- 出售塔前不弹出确认对话框（右键 = 明确意图）——但出售立即生效，无可撤销
- V1.0 评估是否需要"撤销上一步"（Undo）功能
- 方块放置前检查路径可达性——不会让玩家堵死自己的防线

## 6. Platform-Specific Notes

### Windows / macOS Desktop
- 纯键盘操作不在 MVP 范围内（鼠标独占）
- V1.0 评估键盘快捷键（数字键选塔、空格开始波次）
- 窗口模式支持: 全屏 (默认) + 窗口化
- 窗口可调整大小——HUD 布局基于锚点自适应

## 7. Testing Checklist

在 QA 签核前验证:
- [ ] 所有 8 个交互模式在色盲模拟器下可辨识（Protanopia / Deuteranopia / Tritanopia）
- [ ] 完全静音下完成一局游戏（10 波以上）——无信息缺失
- [ ] 所有 UI 文字 ≥ 12px，核心 HUD ≥ 16px
- [ ] 右键菜单合星在 3 秒内完成（与拖拽合星对比——测试 5 人）
- [ ] 无闪烁频率 > 3 次/秒
- [ ] 棋盘格 (56×56px) 点击准确率 100%（50 次随机点击测试）

## 8. Open Questions

- **屏幕阅读器**: Godot 4.5+ AccessKit 支持——V1.0 是否需要？桌面塔防的屏幕阅读器使用场景是什么？
- **键盘导航**: V1.0 是否需要完整的键盘导航（Tab 在 UI 元素间移动、Enter 确认、Esc 取消）？
- **Undo 功能**: 出售/移除操作是否需要撤销按钮？当前右键即时生效，不可逆。
- **高对比度模式**: 是否需要独立的高对比度 UI 主题（如黑白+单强调色）？
- **自定义颜色**: 是否需要让玩家为不同 CellState 选择自定义颜色（如色盲玩家将"红绿"改为"蓝橙"）？
